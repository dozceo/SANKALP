# Genkit Flow Observability & Logging Audit

**Date:** 2025-05-23
**Scope:** `src/ai/flows/`
**Goal:** Identify logging gaps (Inputs, Outputs, Errors, Latency) and recommend improvements.

## Summary

Most flows lack consistent structured logging. While some have basic start/end logs, detailed input parameters, output results, and execution latency are frequently missing. This makes debugging production issues difficult.

## Recommendations

1.  **Standardize Logging Wrapper:**
    Create a shared wrapper or middleware for all flows that automatically logs:
    -   **Start:** Flow name, timestamp, input parameters (sanitized if PII).
    -   **End:** Flow name, timestamp, duration (latency), success status.
    -   **Error:** Stack trace, input context.

2.  **Add Latency Tracking:**
    Implement `console.time` / `console.timeEnd` or explicit timestamp subtraction around the core logic of each flow.

3.  **Structured JSON Logging:**
    Move from `console.log('Message:', value)` to `console.log(JSON.stringify({ event: 'FlowStart', flow: 'Name', input: ... }))`. This allows log aggregators to parse fields.

4.  **Specific Fixes:**
    -   **High Priority:** Add logging to `custom-cognitive-chatbot.ts`, `speech-to-speech.ts`, and `text-to-speech.ts` as they are currently "flying blind".
    -   **Medium Priority:** Enhance `smart-revision-planner.ts` to log the final revision list generated by the LLM.

## Implementation Example

```typescript
export async function myFlow(input: Input): Promise<Output> {
  const start = Date.now();
  console.log(JSON.stringify({ event: 'FlowStart', flow: 'myFlow', input }));

  try {
    const result = await runFlow(input);
    const duration = Date.now() - start;
    console.log(JSON.stringify({ event: 'FlowSuccess', flow: 'myFlow', duration, result }));
    return result;
  } catch (error) {
    const duration = Date.now() - start;
    console.error(JSON.stringify({ event: 'FlowError', flow: 'myFlow', duration, error }));
    throw error;
  }
}
```
